# Project status

Read `research.yaml`, the current sprint decision, literature artifacts, experiment records, `docs/novelty.md`, `paper/claims.md`, and data documentation as applicable. Treat missing or stale records as findings.

Report the research question, project mode, current sprint and gate, strongest validated evidence, contradicted assumptions, open risks, blockers, and next decision. Cite repository paths and MLflow run IDs rather than relying on conversation history. Separate completed work from work merely planned, and distinguish live-verified integrations from mocks.

Do not turn a status request into a new experiment or publication claim. If repository sources disagree, surface the inconsistency and identify which decision record should resolve it.
